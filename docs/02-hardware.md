## 2. 底板引脚占用表 ⭐

**这张表是接线的唯一依据。** 全部来自官方 Wiki 各实验章节原文。`【原文】`

| 功能 | 引脚 | 备注 |
|---|---|---|
| **模拟输入（ADC）** | **PA3** | ADC12_IN3。底板只有**一路**模拟输入 |
| **测频 / 比较器输出** | **PA6** | LM393 输出 → 定时器输入捕获 |
| LCD SPI0 SCK | PA5 | AF0 |
| LCD SPI0 MOSI | PA7 | AF0。**未引出 MISO** |
| LCD RES / CS / BL / DC | PB5 / PB6 / PB7 / PB8 | |
| PWM 输出（外接排针） | **PA2** | 板上简易函数发生器 |
| 三个独立按键 | PB13 / PB14 / PB15 | 一侧接地，软件消抖 |
| 底板 LED2 / LED3 | PC14 / PC15 | **低电平点亮** |
| 串口 | PA9 (TX) / PA10 (RX) | USART1 |

### 🚫 硬冲突：绝对不要用 USART2

**PA2 和 PA3 都被底板占用**（PA2 = PWM 输出，PA3 = 模拟输入）。
USART2 正是 `PA2/PA3` → **USART2 在这个组合上完全不可用。**

这条不是"建议"，是硬冲突。谁要是把上位机链路选到 USART2，会同时毁掉模拟输入和 PWM。

## 3. 核心板引脚与特性

| 项目 | 结论 | 证据 |
|---|---|---|
| 板载 LED | **PC13，高电平点亮** | `【原文】`（与 Blue Pill 的低电平点亮相反，容易踩） |
| 用户按键 | **没有**，只有复位键 | `【原文】` |
| USB | **PA11 = USBDM / PA12 = USBDP**，且 Type-C 直连这两脚 | `【佐证】` |
| 板载 USB 转串口芯片 | **没有**（不是 CH340，也不是 CP2102） | `【原文】` |
| SWD 调试口 | 有，丝印 `3V3 / DIO / CLK / GND`；DAP-Link 可烧录 | `【原文】` |
| 晶振 | 8 MHz HSE + 32.768 kHz LSE | `【推断】`（板上有两颗晶振是原文，具体频率是推断） |
| LDO | ME6211C33M5G-N（SOT-23-5） | `【佐证】` |
| BOOT 跳线 | 丝印 `BT0 / BT1`，各 3 脚 | `【原文】` |
| 板尺寸 | 53.34 × 22.86 mm（经典 Blue Pill 尺寸） | `【原文】` |
| PA12 上拉 | 疑似 1.5 kΩ 硬上拉（无 soft-connect 控制） | `【待测】` |

### 🔑 与 GD32E230 核心板逐脚兼容

两块板的 2×20 排针定义**逐脚完全相同**（已逐字比对 LCEDA 官方引脚图 `【原文】`）：

- `PA3` = 右排 28、`PA5` = 30、`PA7` = 32
- `PB5` = 左排 13、`PB6` = 14、`PB7` = 15、`PB8` = 16

**所以底板可以直接换核心板。** 但有一个能力差异——

## 4. ⚠️ 最重要的发现：没有板载串口桥

### 立创 GD32E230 核心板 vs 地阔星

| | GD32E230 最小系统板 | **地阔星 STM32F103C8T6** |
|---|---|---|
| 板载 CH340N | **有**（背面 SOP-8） | **没有**（背面只有 SOT-23 LDO） |
| Type-C 出 COM 口 | 是 | **否**，Type-C 直连 MCU 的 PA11/PA12 |
| "一根线搞定下载+串口" | 可以 | **不行** |

官方入门手册原文：**"我们想要使用串口下载需要一个 USB 转 TTL 模块。具体的可以自行购买。"** `【原文】`
官方给的下载路径只有三种：DAP-Link / ST-Link V2 / 外接 USB-TTL 串口 ISP。`【原文】`

### 这意味着什么

上游项目（GD32 版）的"插上 Type-C 就是一个 COM 口"在换核心板后**不成立了**。
我们的上位机链路必须二选一：

| 方案 | 引脚 | 优点 | 缺点 |
|---|---|---|---|
| **A. USB CDC** ⭐ | PA11/PA12 | 板载 Type-C 直连；带宽最高（500–900 KB/s）；不需额外硬件 | 要自己写 USB device 固件；PA12 硬上拉可能需要在连接后补一次复位 |
| **B. 外接 USB-TTL** | PA9/PA10（USART1） | 最省事；Wiki 有现成教程；两脚都空闲 | 板上没有数据口，线要从排针飞出来；带宽 92 KB/s @921600 |
| ~~C. USART2~~ | ~~PA2/PA3~~ | — | 🚫 **硬冲突，不可用** |

> **建议**：**P1 先用方案 B 打通链路**（最快出成果，不用碰 USB 协议栈），
> **P2/P3 再上方案 A** 拿带宽。
> 好在协议层完全不关心底层链路 —— `DevicePort` trait 屏蔽了差异，
> **两种链路都实现，协议一个字都不用改**（这正是 ADR-003 把传输层抽象出来的回报）。
>
> ⚠️ 注意：F103C8T6 的系统 ROM bootloader 是否支持原生 USB DFU 存在争议，
> **不要把"USB DFU 一键下载"当可靠前提** `【佐证】`。

## 5. 模拟前端（底板）

来自官方 Wiki 原图与 BOM：`【原文】`

```
BNC ──► SW3（X1 直连 / X50 衰减）──► SW2（AC/DC 耦合）──► TL072IP ──► PA3
                                                            │
                                                            └──► LM393P ──► PA6
```

| 环节 | 器件 | 参数 |
|---|---|---|
| 耦合 | SW2 + 100 nF | AC 耦合隔直；原文按自谐振频率论证 100 nF 足够 |
| 衰减 | SW3 + 分压网络 | 直连（X1）或 `20k/(510k+470k+20k) = 1/50` |
| 缓冲/放大 | TL072IP | 一路跟随器，一路比例放大 `Vo=(5−Vin)/2` |
| 量程 | — | 低压 **−1.6 V ~ 5 V**；高压 **−80 V ~ 250 V** |
| 比较器 | LM393P | 滞回，`Uth=2.214 V / Utl=2.172 V` → PA6 输入捕获 |
| 负压 | XD7660 + 2 电容 + 1N4148 | 理论 −5 V，实测约 −4.3 V，供运放处理负半周 |

### ⚠️ 量程切换是机械拨动开关

**SW2（AC/DC）与 SW3（X1/X50）都是手拨的机械开关，AI 无法程控。**
要支持自动量程必须改板（换继电器/模拟开关，如 CD4053）。

> 这是一条**硬件**约束，不是软件待办 —— 决策记录里没有对应条目（ADR-001~011
> 都不涉及量程开关）。相关讨论在本节与 [`README`](../README.md) 的「硬件上必须
> 先知道的三件事」第 3 条。

### ⚠️ TL072 带宽偏软

TL072 的 GBW 只有 3 MHz，对 400 kHz I2C 的 300 ns 边沿已经偏软，
1 MHz 的 120 ns 边沿完全不够。`【推断】`
这正是 ADR-005 把协议解码放到**数字通路**（LM393 → 输入捕获）的原因之一 ——
数字通路不经过 TL072。

## 7. 🚧 待决策：单通道 vs 双通道

**底板只有一路模拟输入**（BNC → TL072 → PA3），
而 I2C 解码需要 SCL/SDA **两路同时刻采样**（时差必须 ≪ tSU;DAT：
标准 250 ns / 快速 100 ns）。`【原文】`

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **① 改板加第二路前端** | 复制一路 TL072 + 第二路 ADC（PA6 之外的可用脚） | 真正的双通道模拟示波器 | 要改板、打样、重焊 |
| **② 单通道 ADC + 一路数字** ⭐ | 一路走 ADC 看模拟质量，另一路走 LM393 → PA6 捕获 | **不改板**，立刻可做 | 两路时间基准不同；数字那路只有 0/1 |
| **③ 纯数字双通路** | 加一颗比较器，两路都走定时器捕获 | 协议解码 100% 可靠，成本 ~1 元 | 完全放弃模拟视图，退化成逻辑分析仪 |

**建议**：
- **P0–P3 用方案 ②** 跑通全链路（不改板，最快出成果）
- **P4 做方案 ①** 作为产品形态，同时保留 ③ 的双数字通道作为可选模式

**为什么要保留模拟通路**：项目的差异化能力（电平裕量、上拉强度、振铃）
**全靠 ADC 通路**。走纯方案 ③ 就丢掉了这个卖点。

## 9. 实板必测清单

拿到板子后**第一件事**，逐条量并回写到本文： `【待测】`

| # | 测什么 | 为什么 |
|---|---|---|
| 1 | Type-C 的 D+/D− 是否直通 PA11/PA12 | 决定 USB CDC 方案是否成立 |
| 2 | PA12 对 3.3 V 的阻值是否 1.5 kΩ | 硬上拉会导致"上电后要复位一次才能被识别" |
| 3 | 核心板供电是否与底板 5V 倒灌 | 有社区帖指出 Type-C 为直供（VBUS 直连 5V，无二极管） |
| 4 | TL072 输出的实际源阻抗 | 决定 ADC 采样时间档（1.5 周期要求 ≤0.4 kΩ，7.5 周期放宽到 ~19 kΩ） |
| 5 | LM393 输出到 PA6 的实际阈值与边沿 | 验证数字通路可用性 |
| 6 | 8 MHz HSE 实际频率与精度 | 决定 857 kSPS 采样率与 I2C 解码的相位稳定性 |
| 7 | 底板 PA3 处的直流工作点 | 验证 `Vo=(5−Vin)/2` 的中点是否为 2.5 V |

**测完请更新本文并去掉对应的 `【待测】` 标记** —— 这是团队纪律的一部分。
