## ADR-001 · 固件语言选 C 而非 Rust

**状态**：已决定 · 2026-10-01

**背景**：固件语言要在两条路里选：Rust（`embassy-stm32`，能与上位机共享协议结构体、编译期防 drift）或 C（复用成熟生态与现成驱动）。

**方案**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| Rust + embassy-stm32 | 协议结构体三端共享，编译期防漂移 | 要抛弃立创已调好的 C 固件与屏幕驱动；F103 的 embassy 生态资料少；团队上手成本高 |
| **C + HAL/标准库** | 直接复用立创开源工程与 STM32版本 分支；F103 生态最成熟；CubeMX 可视化配置 | 跨语言协议一致性要靠测试保证 |

**决定**：**固件用 C**。

**依据**：
- 立创开源工程的固件是 GD32E23x 标准外设库 C 代码，且有专门的 STM32版本 分支
- 屏幕驱动（ST7735）、编码器、ADC 采集这些底层代码已经调好，重写成本高
- 团队要 8 周出成果，不是学 Rust 的时间
- Rust 在**上位机**侧照样发挥内存安全的优势，编译期防 drift 的价值不丢失

**代价**：失去 postcard 的编译期结构体共享 → 用**黄金测试向量 + 两端 CI** 补偿（见 ADR-002）。

**何时重新考虑**：若 F103 固件需要重写（例如 P4 换 STM32G431），且团队已熟练 Rust。

## ADR-002 · 协议用「手写定长小端二进制」而非 postcard

**状态**：已决定 · 2026-10-01 · 依赖 ADR-001

**背景**：跨语言（C 固件 + Rust 上位机）的线上编码格式需要在 `postcard`（Rust serde 的 no_std 紧凑格式，「同一份结构体同时编译到 PC 与 STM32」以杜绝 drift）与手写定长格式之间选型。

**决定**：**改为手写定长小端二进制**，`docs/03-protocol.md` 为契约，`vectors.json` 为跨语言门禁。

**依据**：
- postcard 的价值**只在两端都是 Rust 时成立**。固件是 C（ADR-001）→ C 侧要手写 LEB128/zigzag/长度前缀，postcard 无官方 C 实现也无代码生成，**收益归零**
- 变长编码使字段偏移不可预测 → C 侧边界检查、黄金向量编写、hexdump 目视调试都更难
- 定长格式让「解析顺序固定：读头 → 验 LEN → 读 payload → 算 CRC」成为可能，显著降低越界风险

**补偿机制**（这是本决策能成立的关键）：

1. `proto/tests/vectors.json` 是跨语言唯一契约，**两端跑同一份向量**
2. `App/` 层不依赖 HAL → C 端逻辑可在 PC 上用 `gcc` 编译测试
3. CI 门禁：C 向量测试 + `cargo test` 全绿才能合并
4. **上位机 + MCP 侧仍保留"命令只定义一次"**：Rust 类型 → `serde` / `schemars` → MCP JSON Schema 自动生成

**代价**：改一条消息要动四处文件。用 CI 强制纪律来兜。

**何时重新考虑**：固件若迁移到 Rust → 把 codec 换回 postcard，其余不动。消息数 > 50 或出现第二台设备 → 评估 nanopb。

## ADR-003 · 主传输走 UART / USB CDC，放弃以太网

**状态**：已决定 · 2026-10-01 · 细节由 [ADR-009](#adr-009--传输层选型usb-cdc-为主usart1-为备禁用-usart2) 落实

**背景**：波形数据的主传输通道需要在以太网、UART、USB CDC 之间选型。

**决定**：**主传输改为 USART1（外接 USB-TTL）或 USB CDC**。

**依据**：
- **STM32F103C8T6 没有以太网外设**（无 MAC，无 RMII）—— 这是物理事实，不是取舍
- 该型号无 FSMC、无 SDIO，外挂方案要么慢要么不成立
- 核心板 Type-C 直连 PA11/PA12，所以 USB CDC 是**板载可达**的（核实于 ADR-009）

**代价**：
- 带宽从「够传波形」降到 `92 KB/s`（921600）或 `500–900 KB/s`（USB CDC）
- 857 kSPS 原始流在**任何**链路下都不可能 → 必须突发采集 + 设备侧降采样

**连带影响**：`04-performance.md` §4 的链路预算表；`03-protocol.md` §6.3 的分片规则。

**何时重新考虑**：外挂 W5500/ENC28J60 SPI 模块（P4 可选）。

## ADR-004 · 放弃深存储，深度锁定 4096 点

**状态**：已决定 · 2026-10-01

**决定**：单次采集 **4096 点**（8 KB 环），不设外扩存储。

**依据**：
- `F103C8T6` 是中容量型号，**没有 FSMC** → 并行 SRAM/SDRAM 不可行
- 20 KB SRAM 里能留给波形缓冲的现实上限是 8–12 KB
- 计算如下：双通道 12-bit 各存 u16 = 4 B/点 → 2048 点 = 2.39 ms；单通道 4096 点 = 4.78 ms
- **而对 I2C 够用**：100 kHz 下一次 2 字节寄存器写约 270 µs，4.78 ms 能抓 ~17 个事务

**代价**：
- 「1 M 点深存储」、「1024 点 float FFT」（复数数组就要 8 KB）全部不成立
- 必须用定点、分段采集、降采样、「采集-上传-清空」循环模式

**何时重新考虑**：换 F103RC/ZE（带 FSMC）或加 SPI SRAM（仅适合非实时回放）。

## ADR-005 · ★ 双通路架构（ADC 模拟通路 + LM393 数字通路）

**状态**：已决定 · 2026-10-01 · **本项目最重要的架构决策**

**背景**：项目的原始痛点是抓 I2C 波形做调试。定量分析得出结论：

| I2C 速率 | 判定 START/STOP 所需采样率 | F103 857 kSPS |
|---|---|---|
| 100 kHz | 0.50 MSPS | ✅ 舒适 |
| 400 kHz | 3.33 MSPS | ❌ 差 3.9× |
| 1 MHz | 7.69 MSPS | ❌ 差 9× |

更致命的是**采样相位拍频**：857 k @ 400 kHz 时采样相位只有 15 个离散值，两颗晶振 40 ppm 差会让解码**以 ~62 ms 为周期时好时坏地闪** —— 这是采样系统性问题，**软件补不了**。

**方案**：

| 方案 | 说明 | 评价 |
|---|---|---|
| A. 双 ADC 交织 2 MSPS | 把单线推到 1.71 MSPS | ❌ 400 kHz 仍需 5 点/bit 中的 2.1，且只能单线、源阻抗锁死 0.4 kΩ、fs/2 处注入失配花纹（正好落在 I2C 谐波带） |
| B. 采样相位自对准 | 固件 DLL 锁到比特中点 | ⚠️ 只能救 400 kHz，1 MHz 无解；需几百比特锁定期 |
| **C. 双通路：数字通路解协议 + 模拟通路看信号** | **板上现成的 LM393 → TIM 输入捕获** | ✅ **100k/400k/1MHz 全部可靠** |

**决定**：**方案 C**。

**依据**：
- 板上那颗 **LM393P 滞回比较器**（原设计只用来测频率）接输入捕获后 → **72 MHz / 13.9 ns** 边沿时间戳，等效 **~72 MSPS**
- 边沿驱动解码 → **免疫混叠、免疫采样相位问题、免疫时钟拉伸**
- 两条通路完全互补：
  - 数字通路只有 0/1 → 丢失电平裕量
  - ADC 通路 857 kSPS → 给不了高速协议
  - **合起来 = 协议对不对 + 信号好不好**，这是 10 元逻辑分析仪和普通示波器都给不了的

**代价**：
- 占用 2 个定时器输入通道与中断/DMA 负载
- 两条通路需要时间对齐（误差目标 < 1 µs）
- 板子只有一路 LM393 → 若要做双线纯数字解码需加一颗比较器（见 ADR-010）

**对外声明**（写进所有文档）：
> 协议解码 100 kHz ~ 1 MHz（数字通道）；模拟波形 100 kHz 保证 / 400 kHz 有条件 / 1 MHz 不支持（ADC 单次）。

**何时重新考虑**：换成 STM32G431/G474（4–5 MSPS）后，ADC 单通路即可覆盖 400 kHz，但数字通路在 1 MHz 下仍有价值 —— **建议长期保留双通路**。

## ADR-006 · 控制链路永不出现 f32

**状态**：已决定 · 2026-10-01

**决定**：线上协议**禁止 IEEE754 浮点**。

| 量 | 表示 |
|---|---|
| 触发电平 / 偏移 | **ADC LSB 整数**（u16 / i16） |
| 采样率 | 整数 Hz（设备回显量化后的 `actual_hz`） |
| 时长 | 整数 µs |
| 窗口 / 偏移 | 整数样点 |
| 测量结果 | 定点，**字段名自带缩放**：`mean_x256`、`duty_x10000` |
| 将来确有浮点（标定系数） | 统一 **Q16.16（i32）**，写进规格 |

**依据**：
- F103 无 FPU，软浮点慢且在中断上下文危险
- 浮点的线上格式极易被两端误解（NaN/Inf/-0）
- **伏特↔LSB 换算、量程衰减、AC/DC 校正全部留在上位机**，MCU 只认 LSB，不知道"伏特"是什么

**连带**：上位机按设备 `uid` 存标定表，`SET_CHANNEL` 传 LSB，显示层才换算成伏特。

## ADR-007 · 非幂等命令靠「单槽响应缓存」保证重试安全

**状态**：已决定 · 2026-10-01

**背景**：`ARM` 不是幂等命令。链路超时后主机不知道设备到底收到没有 —— 直接重发可能导致"武装了两次"或丢失状态。

**决定**：设备缓存**最近一次的 `(seq, CMD, 完整响应)`**，同一 `seq` 在 1 s 内重发**直接回放缓存**，不重新执行。

**代价**：
- 缓存只有 **1 槽** → **主机不得并发流水多个非幂等请求**
- 1 s 过期窗口需要在"重试太慢"与"陈旧回放"之间权衡

**配套规则**（写进 `03-protocol.md` §8）：
- 超时后**不要立刻重发** → 先清空接收缓冲、重同步链路，再按原 seq 重发
- 幂等命令（`STOP` / `FORCE_TRIGGER` / `PING`）直接重发
- 连续 N 次失败 → 上报链路故障

## ADR-008 · `App/` 层禁止依赖 HAL

**状态**：已决定 · 2026-10-01

**决定**：`firmware/App/` 下所有文件**不许 `#include` 任何 HAL / 寄存器头文件**。硬件访问必须经 `firmware/Hardware/` 的抽象接口。

**依据**：
- 这是**「无硬件也能开发」的根基**：`proto_task.c` / `i2c_decode.c` / `measure.c` / `trigger.c` 可以在 PC 上 `gcc` + mock 编译测试
- 三个人里只有一个能同时拿到板子 → 不这样做，另外两个人只能干等
- C 端黄金向量测试也需要这个前提

**执行**：CI 加一条检查 —— `grep -rn '#include.*\(stm32\|hal_\|gd32\)' firmware/App/` 有结果就失败。

## ADR-009 · 传输层选型：USB CDC 为主，USART1 为备，**禁用 USART2**

**状态**：✅ **已核实并决定** · 创建 2026-10-01 · 核实完成 2026-10-01

**背景**：立创 STM32F103C8T6 小蓝板的 Type-C 口是接在板载 CH340 上，还是直接接 MCU 的 PA11/PA12？

**核实结论**（详见 `02-hardware.md` §3–4）：

- 核心板实为 **立创·地阔星 `LCKFB-DKX-STM32F103C8T6`**（不是"极客星"，oshwhub slug `gekuo` = 地阔）
- **板上没有 USB 转串口芯片**。官方入门手册原文要求用户自备 USB-TTL 模块；规格书资源标注图中无串口桥芯片；高清实物图正反面只有一颗 LQFP48 主控 + 一颗 SOT-23 LDO
- **Type-C 直连 PA11(USBDM) / PA12(USBDP)**

**决定**：

| 优先级 | 链路 | 引脚 | 场合 |
|---|---|---|---|
| **P1 期主力** | **USART1 + 外接 USB-TTL** | PA9 / PA10 | 最快打通链路，不用碰 USB 协议栈 |
| **P2 起主力** | **USB CDC** | PA11 / PA12 | 带宽 6–10 倍，板载 Type-C 直连 |
| 🚫 **禁止** | ~~USART2~~ | ~~PA2 / PA3~~ | **PA2 是底板 PWM 输出、PA3 是模拟输入 —— 硬冲突** |

**依据**：
- 上游 GD32 版"插上 Type-C 就有 COM 口"的能力**随核心板更换而消失**，这条不能想当然照搬
- 两条链路在操作系统层都是 COM 口 → **同一个 `SerialDevice` 实现覆盖两者**，无需分叉代码
- 协议层完全不关心底层链路 → 换链路**协议一个字都不用改**

**代价**：
- USB CDC 需要自己写 USB device 固件；且 PA12 疑似 1.5 kΩ 硬上拉，可能得上电补一次复位（`【待测】`）
- 外接 USB-TTL 方案要从排针飞线，没有板载数据口

**缓解设计**：`DevicePort` trait 屏蔽差异，两种链路都实现；`GetCapabilities` 如实上报 `max_tx_payload` 与建议分片大小。

**何时重新考虑**：若实测发现 USB CDC 在该板上不稳定，就长期停留在 USART1（协议不变，只是带宽从 500–900 KB/s 降到 92 KB/s，直接反映为分片更大、实时性更差）。

## ADR-010 · ⏳ 单通道 vs 双通道（阻塞 P4，不阻塞 P0–P3）

**状态**：⏳ **待决策** · 创建 2026-10-01

**问题**：立创底板只有**一路模拟输入**（BNC → TL072 → PA3/ADC_IN3），而 I2C 解码需要 SCL/SDA **两路同时刻采样**（时差必须 ≪ tSU;DAT：标准模式 250 ns、快速模式 100 ns）。

**三个方案**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **① 改板加第二路前端** | 复制一路 TL072 前端 + 第二路 ADC（**引脚待定，不能用 PA6**） | 真正的双通道 I2C 示波器；ADC 模拟通路同时可用 | 要改板、打样、重焊；超出立创原始设计 |
| **② 单通道 ADC + 一路数字** | 一路走 ADC 看模拟质量，另一路走 LM393 → TIM 捕获 | **不改板**，立刻可做 | 两路时间基准不同，需对齐；数字那路只有 0/1 |
| **③ 纯数字双通路** | 加一颗比较器，两路都走 TIM 捕获 | 协议解码 100% 可靠，成本最低（~1 元） | 完全放弃模拟视图 —— 就退化成逻辑分析仪了 |

**建议**：
- **P0–P3 用方案 ②** 跑通全链路（不改板，最快出成果）
- **P4 做方案 ①** 作为产品形态（保留③的双数字通道作为可选模式）

**为什么要保留模拟通路**：项目宣称的差异化能力（电平裕量、上拉强度、振铃）**全靠 ADC 通路**。走纯方案 ③ 就丢掉这个卖点了。

**决定前需要的信息**：第二路 ADC 用哪个脚。

⚠️ **不能用 PA6** —— 它已经被 LM393 的输入捕获占用（见 `02-hardware.md` 引脚表）。
且底板已占 PA2/PA3/PA5/PA6/PA7/PB5~PB8/PB13~PB15/PC14/PC15，
第二路 ADC 只能从 **PA0/PA1/PA4/PB0/PB1** 这几条 ADC 通道里挑（对照引脚图复核后确定）。

## ADR-011 · 仓库许可选 GPL-3.0

**状态**：已决定 · 2026-10-01 · **需团队最终确认**

**背景**：混合许可 —— 上游硬件 GPL-3.0，上游参考代码 MulanPSL-2.0。

**决定**：仓库整体以 **GPL-3.0** 发布。

- 硬件派生作品**必须** GPL-3.0（传染性）

- 统一一个许可证比拆分目录许可更不容易出错

**注意**：
- 上游页面明文**禁止商业性使用** —— 这条独立于 GPL，必须遵守
- **本条目不构成法律意见**，正式参赛/发布前建议由团队确认

**何时重新考虑**：若将来要把上位机代码单独抽出来做成通用库（与硬件无关）。

## ADR-011 · 换用带板载 USB 转串口的最小系统板（取代 ADR-009）

**状态**：✅ **已决定**（**supersedes [ADR-009](#adr-009--传输层选型usb-cdc-为主usart1-为备禁用-usart2)**）· 创建 2026-10-04

> ⚠ **ADR-009 不改写，原样保留。** 它如实记录了 **2026-10-01 那次核实**的结论
> （当时那块板确实没有串口桥）。本条目记录的是**之后换板**导致的结论变更 ——
> 保留两条，读者才看得出这个结论是怎么变的。

**背景**：ADR-009 的核心结论建立在一条事实上 ——

> 「板上没有 USB 转串口芯片。官方入门手册原文要求用户自备 USB-TTL 模块；
> 规格书资源标注图中无串口桥芯片；高清实物图正反面只有一颗 LQFP48 主控 +
> 一颗 SOT-23 LDO」—— 见 `02-hardware.md` §3–4（当时）

**核心板已更换**：现用 **STM32F103C8T6 最小系统板（Blue Pill 尺寸，
Type-C 口，板载 USB 转串口）**，经用户 2026-10-04 确认并提供板厂图。
**该前提不再成立。**

**决定**：

| 优先级 | 链路 | 引脚 | 场合 |
|---|---|---|---|
| **主力** | **USART1（板载 USB 转串口）** | PA9 / PA10 | 插上 Type-C 即出 COM 口，不需外接模块 |
| 备选 | USB CDC | PA11 / PA12 | 带宽 500–900 KB/s，代价是自写 USB device 固件 |
| 🚫 **禁止** | ~~USART2~~ | ~~PA2 / PA3~~ | **PA2 是底板 PWM 输出、PA3 是模拟输入 —— 硬冲突**（与 ADR-009 一致，未变） |

**依据**：

- 板载串口桥使「一根 Type-C 线完成供电 + 串口」成立，P1 期的 bring-up 不再需要飞线
- 两条链路在操作系统层**都是 COM 口** → 同一个 `SerialDevice` 实现覆盖两者，
  **协议层一个字都不用改**（这条自 ADR-009 起未变，也是当初把链路选择做成可替换的收益）
- USB CDC 保留为备选：一旦实测板载串口桥在高波特率下不稳，仍有带宽更高的退路

**代价**：
