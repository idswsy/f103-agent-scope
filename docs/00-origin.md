# 00 · 项目由来与定位

## 一句话

把「学长想做的 AI 可控示波器」和「手头这块立创开源示波器板」合成一个**能真正做出来**的项目。

---

## 三条并行的输入

### 输入 1：学长的方案（F407 路线）

2026-09-24，马忠学学长提供了一个完整设计方案《可被 AI Agent 控制的 STM32 示波器》，核心主张：

| 主张 | 是否被本项目采纳 | 理由 |
|---|---|---|
| 命令只定义一次，固件/上位机/Agent 三端复用 | ✅ **完全采纳** | 消除多边同步 drift，是本项目最值钱的原则 |
| `AA 55` 帧头 + seq + crc16 的帧格式 | ✅ **采纳** | 设计合理，直接沿用 |
| `DevicePort` trait 解耦传输层 | ✅ **采纳** | 模拟器一等公民的前提 |
| 模拟器一等公民，无硬件也能开发 Agent | ✅ **采纳** | 本项目 P0 阶段的核心依赖 |
| `GetCapabilities` 能力协商 | ✅ **采纳** | F103 能力受限，这个机制反而更必要 |
| 上位机用 Rust | ✅ **采纳** | 内存安全 + 学长已用 Rust 验证过 egui 桌面应用可行 |
| postcard 共享结构体（Rust 定义，两端编译） | ❌ **改为手写定长 C 结构** | 固件用 C，postcard 的编译期共享优势归零，反而增加 C 侧编解码负担 |
| 主通信走以太网（F407 自带 MAC） | ❌ **改为 UART / USB CDC** | F103C8T6 **没有以太网外设** |
| FSMC 外挂 SRAM 做深存储 | ❌ **放弃** | F103C8T6 是**中容量型号，没有 FSMC** |
| 三 ADC 三重交替 7.2 MSPS | ❌ **降级到 857 kSPS** | F103 只有 2 个 ADC，且 72MHz+USB 下 ADCCLK 只能到 12MHz |
| 固件用 Rust（embassy-stm32） | ❌ **固件用 C** | 要复用立创开源工程已调好的 C 固件与屏幕驱动 |
| 波形不要全量塞给 LLM | ✅ **采纳并强化** | 三层 token 防护，见 `03-protocol.md` |

> 学长的 F407 方案本身没问题 —— 是**换硬件**导致四个维度（传输、采样率、存储、解码）必须整体重做。

### 输入 2：立创开源硬件（实际手头的板子）

《简易数字示波器设计（入门版）》—— 立创开源硬件平台课程案例项目。

- 结构：**核心板 + 插件底板**，全直插器件，适合入门焊接
- 核心板可换：立创 GD32E230 小板 / CW32F030C8T6 小蓝板 / **STM32F103C8T6 小蓝板** ← 本项目选这个
- 模拟前端：BNC → 拨动开关（AC/DC、X1 或 1/50 衰减）→ TL072IP（跟随器 + 比例放大 `Vo=(5−Vin)/2`）→ ADC
- 测频通路：LM393P 滞回比较器 → 定时器输入捕获
- 电源：Type-C **仅供电**，XD7660 产生 −4.3V 负压供运放测负半周
- 交互：EC11 旋转编码器 + 3 按键 + 1.8 寸 TFT（ST7735，128×160，四线 SPI）
- 量程：低压 −1.6V~5V；高压 −80V~250V

**上游最大的缺口**：现有固件只做本机采集+屏幕显示，**没有任何对外命令协议、没有上位机接口、没有波形导出通道**，Type-C 还是纯供电。
换句话说 —— **接口层要我们从零做**，这正是本项目的软件工作量所在。

### 输入 3：学长的 exe（行为规范书）

`I2C示波器_改良版.exe` 经二进制逆向确认：

- 技术栈：**Rust + egui 0.29 / eframe / egui_plot / glow**（不是 Tauri）
- PE32+ x86-64，无壳，单 `main.rs`，5.3 MB，构建于 2026-09-22
- **通信栈为零**：全二进制搜不到 `serialport` / `tokio` / `baud` / `postcard` / `stm32` 任何痕迹

也就是说，**这个 exe 不能连硬件** —— 它是纯 CSV 离线分析工具（吃 Rigol 导出的 CSV）。

但它把 **I2C 解码器的行为规范**完整暴露了出来，可以直接当需求书：

- 默认 `CH1 = SCL`、`CH4 = SDA`，通道可重选
- 阈值判定（低/高，单位 V）+ 去抖（debounce）可调
- 解码为 START / 地址 / ACK / NACK / 数据 / STOP 的帧序列，显示「共 N 帧」
- 原始模拟波形 + 解码泳道（lane）双层视图，泳道位置与配色可调
- 无信号时告警；解不出时提示检查通道/阈值/去抖
- 导出 `i2c_decode.txt`

**这个规范被本项目原样继承到 `scope-core` 与 MCP 工具设计里。**

## 本项目最终定位

> **一台给 AI 用的调试眼睛**：能自动抓 I2C/串口总线、解出协议、并同时告诉你信号质量好不好。

不是计量仪器。KPI 不是「多少位有效精度」，而是：

1. **Agent 能不能一句话拿到想要的波形/协议/测量结果**
2. **拿到的东西对不对**（解码必须 100% 可靠，宁可说"不知道"也不给看似精确的垃圾数）

## 诚实边界（写死在文档里，防止后期被当成 bug）

| 能 | 不能 |
|---|---|
| I2C 协议解码 100k / 400k / 1MHz | I2C 时序合规性验证（tSU;DAT / tr 的 ns 级判定） |
| 模拟观察 ≤ 100 kHz | 带宽 > 0.5 MHz |
| 双通道同步 857 kSPS | 1 MSPS 与 USB 并存 |
| 单次 4096 点 | 深存储 / 外扩 SRAM |
| 低频、电源纹波、音频、总线分析 | 计量级测量、THD / SFDR、12-bit 绝对精度 |
| 高/低压两档（机械拨动开关切换） | AI 程控量程（需改板，见 P4） |
